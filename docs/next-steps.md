# Next Steps

## 可以继续做什么

### 1. 稳定性与测试

- 给 [src/game/domain/](../src/game/domain/) 增加单元测试，覆盖计分、发牌、结算与收益计算。
- 给 [src/game/hooks/](../src/game/hooks/) 增加少量流程测试，验证 NPC/Joker/结算推进时序。
- 维护 [docs/manual-regression-checklist.md](../docs/manual-regression-checklist.md)，并在每次结构性改动后走一轮固定人工回归。

### 2. 工程质量

- 清理剩余小型维护风险，例如把视图层中的硬编码规则值收回常量。
- 继续压缩 [src/AbyssalBlackjack.jsx](../src/AbyssalBlackjack.jsx) 的装配负担，必要时引入更清晰的屏幕状态适配层。
- 给关键规则与流程模块增加更明确的文件头说明，便于未来继续拆分或移植。

### 3. 对外发布质量

- 给项目补一套正式截图或短演示 GIF，用于仓库首页展示。
- 整理版本更新记录，说明当前 Web 版已完成的核心特性。
- 根据需要补充英文简介和更清晰的玩法说明。

### 4. 游戏迭代

- 在保持原版表现不变的前提下，补充非破坏性的辅助功能，比如音效开关、动效开关、速度选项。
- 如果后续决定扩展玩法，优先从配置化卡池、阶段参数、商店参数入手，而不是直接改写规则主干。

### 5. Unity 迁移准备

- 继续减少规则层对 React 运行时的依赖。
- 评估把规则输入输出整理成更明确的数据对象，方便未来在 Unity 中复用。
- 在正式启动 Unity 迁移前，先冻结 Web 版行为并建立最小回归测试集。
